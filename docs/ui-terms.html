Looking for the three dots?

Top-right ⋯ on phone / Android → call it the More menu.

Also searchable as: three dots · ⋯ · ellipsis · overflow · top right · top-right menu · More button

Chrome & controls

UI shell pieces — where they sit and what to call them when briefing or filing feedback. Visible label (or aria-label) is listed when the app has one.

More menu Mobile · top right

The ⋯ (three dots / ellipsis) button in the top-right of the mobile header. Opens a dropdown of secondary destinations: Templates, Dashboard, History, Tags, Archived, Settings. Primary destinations (Today / Inbox / Upcoming) stay on the bottom tabs instead.

Say: More menu. Aliases OK: ⋯ menu, three-dots menu, overflow menu. Prefer “More menu” in product writing — it matches the in-app accessible name.

nav.more → “More” · aria-label on button + menu · MobileHeader.tsx

Bottom tabs (primary); Sidebar (desktop equivalent of both tabs + More)

Search Mobile header · top right · left of ⋯

Magnifier-style ⌕ control next to the More menu. Opens the Search view (active / non-archived tasks). Also a sidebar link on desktop.

nav.search · aria-label on mobile header icon

Mobile header Phone / Android · top of screen

Top bar with the current view title (e.g. Today, Inbox) on the left, Search + More menu on the right. No product string for the bar itself — use “mobile header” in docs.

.mobile-header · MobileHeader.tsx

Bottom tabs Phone / Android · bottom of screen

Primary navigation strip with three tabs: Today, Inbox, Upcoming. Tab labels use the same strings as sidebar / nav. Screen-reader name for the strip is hard-coded English “Primary” (not localized). Badges: Today shows a red numeric count of remaining open tasks; Inbox shows a red dot (no number) when there is at least one open task with no pinned tag — a notice to look, not an unread tally. Upcoming has no badge. Hidden when the corresponding count is zero.

Aliases: tab bar, bottom nav.

nav.today / inbox / upcoming · BottomTabs.tsx · aria-label="Primary" · .bottom-tab-badge / .bottom-tab-badge-dot

More menu (secondary destinations)

Sidebar Desktop · left column

Full desktop nav: Today, Inbox, Upcoming, Search; pinned tags; then Tags, Archived, Templates, Dashboard, History, Settings. On phone these split across bottom tabs + More menu — there is no sidebar on mobile. Sidebar counts (muted, not red badges): Today shows remaining open tasks; Inbox and Upcoming show no count (Inbox presence is the mobile red dot only). Pinned tags / Archived / Templates keep inventory counts.

sidebar.* · Sidebar.tsx · “Pin to sidebar”

Title bar Windows desktop · window chrome

Custom window controls: Minimize / Maximize / Restore / Close. Desktop only.

titlebar.* · DesktopTitlebar.tsx

Composer Today / Inbox / Tag views · top of list

Quick-add field. Placeholder: “What needs doing? …” / aria-label “New task”. Parses tags, dates, and estimates from shorthand. “Add task with more options…” expands into the full task editor.

Aliases: quick-add, new-task line. Prefer “composer” in engineering; “quick-add” is fine for users.

composer.placeholder · aria · expand

Task row Any task list

One line in a list: checkbox, title, tags/dates, timer controls. Tapping opens the task editor. Ghost rows (from recurring templates) look similar but are not stored tasks until promoted.

taskRow.* · ghostRow.* · .task-row

Modal / editor dialog Overlay over the current view

Full-screen or centered dialog with backdrop. Main ones: Task editor (edit / new task or template), Tag editor, theme pickers, confirm prompts, update prompt. No single product word in i18n — say “task editor” or “modal” as needed.

taskEditor.* · tagEditor.* · role="dialog" · .modal-backdrop

Idle bar Today / Inbox header area

Shows session idle time (“Idle …”) with Assign / Reset. Session-local — not synced.

today.idle · idle.*

Easy to confuse

Start here for folder / sync language and other look-alike terms.

Desktop (always) · Android (when unlinked)

Folder:

The local data folder path this device uses for its tasks_<device>.db (and related files). On desktop this is the sync directory you pointed at. On Android this is typically the app-private path — not the cloud folder. When Android has a SAF link, this line is hidden so only “Synced folder:” remains (one-folder UX).

Android only (when linked)

Synced folder:

The user-picked SAF folder (often a cloud-drive directory) that the app mirrors to/from. Separate from the local “Folder:” path. Desktop does not show this label — desktop’s “Folder:” already is the sync folder.

Navigation & views

Destinations in the sidebar (desktop) or bottom tabs + More menu (mobile). Every “view” is a computed query over the in-memory document — nothing is stored as a saved view list.

Today Sidebar · bottom tab · header title

Tasks that belong to the current logical day: start/due coverage for today, overdue due-only tasks, or tasks with time tracked today. Completed tasks stay visible here until the day rolls over (so you can undo). Honors Day start. zh-TW: 今日.

nav.today

Inbox Sidebar · bottom tab · header title

Active tasks that have no pinned tag (untagged, or only unpinned tags). Subtitle: “Tasks with no pinned tag”. Not an email-style inbox — it’s the catch-all so those tasks stay reachable from nav. zh-TW: 未分類 (intentional — not 收件匣).

nav.inbox · inbox.subtitle

Archived; Tag views

Upcoming Sidebar · bottom tab · header title

Forward-looking date view for the next N days (N from Settings → Upcoming range). zh-TW: 即將到來.

nav.upcoming · settings.upcomingRange

Search Sidebar · mobile header icon

Search across active (non-archived) tasks. See also chrome entry.

nav.search

Tags Sidebar · More menu · Tags screen

Manage all tags (create, pin, weight, color). Individual pinned tags also appear as sidebar shortcuts to a Tag view. Tags are flat — they do not nest or own tasks; tasks reference tags via tag IDs.

nav.tags

Pin to sidebar; Inbox (no pinned tag); Weight / priority

Archived Sidebar · More menu

List of completed tasks (filterable by search / date). Completing a task archives it from active views; Restore / Reopen brings it back. zh-TW: 已封存.

nav.archived

Complete; Reopen; Restore — same completed_at flag

Templates Sidebar · More menu

Reusable task blueprints stored separately from live tasks. Spawn a fresh task from a template; recurring templates can project “ghost” rows into date views. zh-TW: 範本 (not 任務模板).

nav.templates

Dashboard / recurrence ghosts; Save as template

Dashboard Sidebar · More menu

Activity tracking for selected tags (heatmap or streak). Nav label is “Dashboard” (nav.dashboard); route and some Settings/view keys still say “Recurrence”. zh-TW: 週期 (not 儀表板) — pairs with README「範本與週期」.

nav.dashboard · recurrence.* · settings.recurrenceHeatmapRange

Recurrence tag on templates; Tag view → Statistic tab

History Sidebar · More menu

Recent changes to tasks, tags, and templates (append-only per-device history sidecar, concatenated for reading). Not the same as Archived. zh-TW: 歷程.

nav.history

Settings Sidebar · More menu

Device-local preferences and data-folder / sync linking. Not synced across devices. zh-TW: 設定.

nav.settings

Settings · Data & sync

Section heading Data file. Desktop always shows Device ID + Folder. Android shows Device ID + Folder when unlinked; once SAF is linked it hides Folder and shows Synced folder instead (same one-folder UX as desktop, without renaming SAF as Folder).

Data file Settings section

Section title for device identity and where this device keeps / mirrors task data. Despite the name, the UI shows a folder path (and on Android a separate synced folder), not a single file picker.

settings.dataFile

Device ID: Settings → Data file

Stable id for this install. Names on-disk replicas like tasks_<device>.db and attachments_<device>/ so peers can merge without clobbering each other.

settings.deviceId

Folder: Settings → Data file

Path to this device’s data location (folder_path). Desktop: the folder you chose to hold replicas (usually a cloud-synced directory). Android: local/app path, shown only while SAF is not linked; hidden once a Synced folder is linked so users see one folder line.

settings.dataFolder

Synced folder: (Android only); Choose folder… / Pick folder…

Synced folder: Settings → Data file (Android, linked)

Label + display name of the SAF folder used as a cross-device mirror (e.g. a folder managed by a cloud drive). Push/pull copies this device’s .db and attachments into that folder; local app-private DB remains master on Android.

settings.syncedFolder

Folder: (local path); (linked); Unlink

(linked) Android, when no folder label

Fallback text when a SAF folder is linked but has no display label.

settings.linked

Desktop buttons

Choose folder… / Use default location

Choose folder… — pick a directory (often cloud-synced). May prompt Change data folder? with Copy / Move / Cancel.
Use default location — clear custom folder and return to app default.

Android buttons

Pick folder… / Sync now / Change folder… / Unlink

Pick folder… — first-time SAF link.
Sync now — pull/push now.
Change folder… — re-pick SAF folder.
Unlink — drop SAF link (local data remains).

Change data folder? Desktop transfer dialog

After picking a new desktop folder (or resetting): Copy keeps this device’s files in the old folder and places a copy in the new one; Move transfers then removes only this device’s files from the old folder. Files from other devices in the folder are never touched.

settings.transferTitle · transferCopy · transferMove · transferCancel

Last synced / Not synced yet Android SAF status

When the last successful SAF sync happened, or that none has completed yet. May append conflict count or last error.

settings.lastSynced · notSyncedYet · conflictCount · syncError

access lost, re-pick the folder Android SAF

SAF permission for the linked folder is no longer valid; user must pick again.

settings.accessLost

Attachments note: Settings copy says attachments are “copied into the data folder and synced to your other devices.” That means the shared sync/SAF folder — not Settings themselves.

How task lists are ordered. “Priority” sorts by the highest weight among a task’s tags (not a free-form priority field on the task).

Tasks

Core unit of work. Priority comes from tags; done/archived from completed_at.

Task Throughout

A titled work item with optional dates, tags, notes, estimate, time entries, and attachments.

Start Date / Due Date Task editor · composer

Optional schedule. Today/Upcoming membership uses these (plus time tracking). Due before start is rejected.

taskEditor.startDate · dueDate · composerPreview.start/due

Overdue Today · task rows

Past-due open tasks surfaced in Today (and row badges like −Nd).

today.overdue · taskRow.overdue

Complete / Reopen / Restore Editor · task row · Archived

Complete marks done (sets completed_at) → task leaves active lists (except Today until day rollover) and appears under Archived. Reopen / Restore clear that state.

taskEditor.complete · reopen · taskRow.restore

Archived — not a separate archive flag

Estimated time Task editor · rows

Optional duration budget (e.g. 1h, 20m). Progress and estimate reminders compare tracked time against this.

taskEditor.estimatedSeconds · timeTracking.estLabel

Notes / Attachments Task editor

Markdown notes (edit / split / preview). Attachments are files copied into the data folder; metadata syncs with the Document; blobs sync as files under the device attachment dir.

taskEditor.notes · attachments

Duplicate / Save as template / Delete Task editor → Options

Duplicate creates another task. Save as template copies fields into Templates without changing this task. Delete is permanent (with tombstone for sync).

taskEditor.duplicate · saveAsTemplate · delete

Tags

Priority weight on a tag. A task’s sort priority is the highest weight among its tags. Shown as “priority weight” in the Tags list tooltip.

tagEditor.weight · tags.weightTitle · settings.weight

Which tag a recurring template “recurs under.” Used to suppress ghost rows when a real task already covers that day for that tag.

Time tracking

Time tracked · Start / Stop Task editor · task rows · Today

Running or finished time entries on a task. Concurrent timers allowed. Tracking today can pull a task into the Today view even without dates.

timeTracking.* · taskRow.startTimer / stopTimer

Idle · Assign Today / Inbox header

Session-local idle timer (not synced). Assign unused time to a task as a time entry. See also Idle bar under chrome.

Sync conflicts

Shown when cloud clients leave conflict copies (`*.sync-conflict*` and similar) in the sync folder. Per-entity concurrent edits usually last-write-wins without a conflict file (desktop and Android SAF pull both merge replicas in place).

Sync conflict / Conflict Banner · Conflicts screen · mobile title

conflicts.title · nav.conflict · conflictBanner.*

Choose which side wins for each differing task (or keep both as separate tasks).

conflicts.yours · theirs · keepMine · keepTheirs · keepBoth

Needs product decision

Ambiguities spotted while cataloging. Code behavior is clear; naming/copy may still want a call.

  1. Dashboard vs Recurrence — Nav: “Dashboard”; Settings: “Recurrence heatmap range”; template field: “Recurrence tag”. One product word for the screen?
  2. Data file — Section title talks about a “file” while the UI is folder-centric (and Android has two folder concepts). Rename section to “Data” or “Data folder”?
  3. Folder: on Android — Resolved: when SAF is linked, hide the local “Folder:” line and keep “Synced folder:” only (preserves glossary meanings; one-folder UX like desktop). Unlinked Android still shows Folder: for the app-private path.
  4. Pick folder… vs Choose folder… — Same idea, different strings for Android vs desktop. Intentional platform tone, or unify?
  5. Statistic — Tag tab EN is singular “Statistic”. Prefer “Statistics” / “Analytics”?
  6. Complete vs Archived — Same flag; two UI words. Product language should keep saying completing archives (or pick one verb for user-facing docs).
